# 维护规范

## 规则修改流程

当你发现系统误判时，不直接改 Gate。

先判断问题属于哪一层：

### A. 方法论本身错了
修改 Rules，并同步 Registry。

### B. 方法论没错，但机器识别标准不准确
只修改 Registry。

### C. 单条规则识别正确，但通关条件不合理
修改 Gate。

### D. 判定正确，但反馈方式不好
修改 Agent。

## 禁止事项

- 禁止在 Gate 里新增一条没有 Rule ID 来源的判断。
- 禁止在 Agent Prompt 里偷偷增加新内容标准。
- 禁止为了修复某个个案，加入只对一个案例成立的规则。
- 禁止把案例偏好升级成 BLOCKER，除非能追溯到价值观或明确方法论。


## 反证相关维护原则

禁止新增“所有深度稿必须包含负面案例/反面段落”之类的全局 BLOCKER。
如需引入风险/反例检查，必须设置明确触发条件，并说明其目的是校准判断强度，而非形式上的正反平衡。
