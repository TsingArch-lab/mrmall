# 作者端反馈规范 v0.4.0

## 0. 数据来源硬约束

作者端负面反馈只允许从当前稿件的 `failed_rules[]` 生成。

**No Rule, No Feedback.**

任何负面句子必须在内部携带：
- `supporting_rule_ids`
- `article_evidence`

输出前必须通过 `engine/provenance_validator.py`。

无法追溯到当前 FAIL Rule 的内容直接 DROP。

---

## 一、最终判断

仅使用：
- **可以继续**
- **需要修改**
- **建议停止**

最终判断由程序依据现有 Gate 聚合规则确定，不允许 Feedback Composer 改判。

**达标即可继续。** 模型不得以“仍可优化”为由把 PASS 改成 REVISE。

---

## 二、分项评价

固定五项：
1. 选题价值
2. 证据支撑
3. 观点质量
4. 结构逻辑
5. 表达质量

显示：
- 突出
- 达标
- 有明显问题

其中负面状态必须由对应 Rule FAIL 映射产生；不得凭整体印象降级。

---

## 三、核心诊断

核心诊断不是自由评论区。

只能概括最高严重度、最上游的 FAIL Rule 或同源 FAIL Rule 集合。

内部结构：
```yaml
core_diagnosis:
  text: "..."
  supporting_rule_ids: [I005, E002]
  article_evidence: ["..."]
```

若当前没有可形成负面诊断的 FAIL Rule，则不得为了格式完整制造问题。

---

## 四、问题清单

先对 FAIL Rules 做同源归并，再输出。

每条只包含：
1. 问题是什么；
2. 具体表现在哪里；
3. 为什么命中已有 Rule。

禁止：
- 修改建议
- 修改顺序
- 改写方案
- 推荐标题
- 推荐结构
- 替代观点

### 归并边界

归并后的含义必须满足：

```text
Cluster Diagnosis Meaning ⊆ Supporting FAIL Rules Meaning
```

归并只能压缩，不能扩权。

---

## 五、事实核验

保持五类：
- 已确认
- 基本确认
- 存疑
- 未找到可靠依据
- 明确不符

核验范围严格遵循 `verification_search_spec.md`：
- 客观可核验事实；
- 作者明确归属于外部来源的观点。

不搜索作者自身判断以寻找支持材料。

事实核验结果本身不直接创造 Gate 惩罚；只有当它使既有 Rule（如 G001 / I005 等）FAIL 时，才影响正式质量判断。

---

## 六、值得保留

只列已成立内容资产。不得夹带修改建议。

---

## 七、作者端固定模板

```text
【最终判断】
可以继续 / 需要修改 / 建议停止

【分项评价】
选题价值：突出 / 达标 / 有明显问题
证据支撑：突出 / 达标 / 有明显问题
观点质量：突出 / 达标 / 有明显问题
结构逻辑：突出 / 达标 / 有明显问题
表达质量：突出 / 达标 / 有明显问题

【核心诊断】
一句话。

【问题清单】
1. ...
2. ...

【事实核验】
...

【值得保留】
...
```

作者默认不展示 Rule ID；后台必须完整保留 provenance。
