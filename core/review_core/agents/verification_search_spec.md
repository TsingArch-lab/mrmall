# 事实核验搜索层规范 v0.3c

## 目标

在文章进入作者端反馈前，对全文中可外部验证的信息进行一轮搜索核验。

这一层不是新的内容规则库，也不创造新的内容标准。
它只负责：
1. 识别文章中的可核验事实；
2. 搜索外部来源；
3. 给出核验结果分类；
4. 将核验结果提供给后续 Gate / Chief Editor 作为证据输入。

---


## 0. 核验边界

事实核验搜索层只搜索以下两类内容：

### 1. 客观可核验的事实声明
包括：
- 精确数字
- 时间、地点、面积、金额、排名
- 开业 / 关店 / 进驻 / 改造等具体事件
- 人物身份、职务、履历
- 项目设计与空间事实
- 历史事实
- “首个 / 最大 / 唯一 / 第一”等比较性事实

### 2. 作者明确归属于外部来源的观点
包括：
- “某某曾表示……”
- “某报告认为……”
- “根据某机构研究……”
- 名人名言
- 高管原话
- 报告、研究、访谈中的结论

### 默认不搜索

以下内容如果只是作者自己的分析、判断或推论，默认不进入事实核验搜索：

- “年轻家庭是徐家汇的新需求”
- “这些家庭更愿意为体验支付溢价”
- “家庭消费是世界级商圈形成的必要条件”
- “这个设计会提升用户黏性”
- “这种更新体现了城市文脉延续”
- “某项目正在进入成长周期”

这些内容应由 Rules 判断：
- 证据是否充分；
- 推理是否成立；
- 判断确定性是否超过证据强度。

事实核验搜索层不得为了证明作者观点而主动在互联网中寻找“支持材料”。

核心原则：

**核验事实，不替观点找证据。**

---

## 一、核验对象

全文扫描以下三类内容：

### A. 数据
包括但不限于：
- 销售额
- 客流
- 增长率
- 市占率
- 门店数
- 开业时间
- 面积
- 投资额
- 租金
- 客单价
- 人口
- 交通客流
- 排名
- “首个 / 最大 / 唯一 / 第一”等比较性事实

### B. 案例事实
包括但不限于：
- 项目开业 / 改造 / 调整
- 品牌进驻 / 撤店 / 开店
- 企业动作
- 项目设计事实
- 空间结构
- 历史事件
- 企业战略公开信息
- 具体经营动作

### C. 引语与人物信息
包括但不限于：
- 名人名言
- 企业高管原话
- 设计师 / 创始人 / 从业者发言
- 公开采访内容
- 人物身份、职务、履历

---

## 二、搜索原则

优先级：

1. 官方原始来源
   - 企业官网
   - 项目官网
   - 政府网站
   - 交易所公告
   - 财报
   - 官方公众号 / 官方新闻稿
   - 官方采访实录

2. 权威媒体 / 行业机构
   - 主流财经媒体
   - 权威行业媒体
   - 研究机构
   - 数据机构

3. 可靠二手来源
   - 有明确出处的专业媒体
   - 可交叉验证的报道

不以以下来源单独作为关键事实的最终依据：
- 无来源自媒体
- 聚合转载
- 营销软文
- 无法追溯原始出处的搜索摘要

---

## 三、核验结果分类

每条可核验事实，使用以下五类之一：

### 1. 已确认
存在可靠来源，且与文章表述基本一致。

### 2. 基本确认
核心事实成立，但文章在时间、范围、数字、定语或表述强度上存在轻微偏差，不影响基本事实。

### 3. 存疑
存在相关信息，但不足以支持文章当前说法，或不同可靠来源之间存在冲突。

### 4. 未找到可靠依据
经过合理搜索后，没有找到足够可靠的公开来源支持该事实。

注意：
“未找到可靠依据”不等于“事实错误”。

### 5. 明确不符
可靠来源与文章表述存在直接冲突，或文章中的数字、时间、人物、事件关系明显错误。

---

## 四、搜索输出结构

后台输出：

```yaml
verification_results:
  - claim: "..."
    type: data | case | quote
    status: confirmed | basically_confirmed | questionable | no_reliable_source | contradicted
    source_level: primary | authoritative_secondary | secondary | none
    evidence: "..."
    notes: "..."
```

---

## 五、与 Gate 的关系

事实核验搜索层本身不决定文章 PASS / REVISE / STOP。

它只提供事实核验结果。

后续 Gate 根据已有 Rules 判断这些核验结果是否构成：
- 真实性问题；
- 证据不足；
- 判断超过证据；
- 或不影响继续推进。

因此：

**Search 负责“查清楚”，Rules 负责“什么算问题”，Gate 负责“能不能继续”。**

## 六、作者端展示

作者端反馈中新增：

【事实核验】

按照重要程度列出搜索结果。

示例：

- 已确认：……
- 基本确认：……
- 存疑：……
- 未找到可靠依据：……
- 明确不符：……

只展示与文章质量相关、具有实质意义的核验结果。
无需把所有普通事实逐条堆给作者。

---

## 七、搜索成本控制

为避免无效算力消耗：

优先核验：
1. 精确数字；
2. “首个 / 最大 / 唯一 / 第一”等高风险事实；
3. 支撑核心结论、且本身属于客观事实声明的关键案例；
4. 名人名言、直接引语；
5. 关键时间节点；
6. 文章中承担因果链支点的事实。

普通、低风险、非关键事实可批量搜索或降低优先级。

---

## 八、核心原则

**先核验事实，再评价判断。**


## 九、判断类表述的处理

若作者未声称某判断来自报告、机构或人物，则该判断不因“看起来可以搜索”而进入事实核验。

例如：
- “消费者越来越重视体验”
- “年轻家庭更愿意为品质买单”
- “家庭消费是世界级商圈的必要条件”

这些属于作者判断，应交由 Evidence / Insight Rules 处理。

只有当作者写成：
- “某报告显示，消费者越来越重视体验”
- “某机构研究认为，年轻家庭更愿意为品质买单”
- “某专家指出，家庭消费是世界级商圈的必要条件”

事实核验层才负责搜索并核验其外部归属与原意。
