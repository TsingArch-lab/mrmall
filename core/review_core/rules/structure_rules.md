# 结构规则

> 本文件是人工维护的 Rule Source of Truth。Registry、Gate、Agent、Feedback 均不得反向修改本文件。


## 一、底层逻辑链

### S001｜A/B完整论证闭环

**Stage**
STRUCTURE

**适用类型**
A / B

**严重级别**
BLOCKER

**判定问题**
文章是否完成设问→证据→推导→收束判断？

**通过条件**
核心问题、具体证据、必要推导和判断形成可理解的闭环。文章可以使用多个案例或成绩，但每一组核心材料都应承担解释、比较、递进或验证中的至少一种功能。

**失败条件**
缺少核心问题、证据、推导或收束判断中的任一关键环节；尤其是正文主要由品牌/项目/成绩清单构成，段落之间只在累加“更多、更强、更成功”，没有形成机制推导。

**例外**
- 反证不再作为每篇文章的固定结构要求。
- 商业合作稿允许使用较多正向案例，只要案例之间存在清晰的分析功能，而非纯成绩堆砌。

## 三、反证空间

### S004｜反证内容按需进入正文

**Stage**
STRUCTURE

**适用类型**
A / B / C / D

**严重级别**
MINOR

**判定问题**
正文是否省略了一个已经明显存在、且足以误导读者理解核心结论边界的重要局限？

**通过条件**
一般情况下N/A。文章不需要专门设置反面章节；只要核心判断没有因为省略重大边界而产生实质误导，就视为通过。

**失败条件**
文章材料本身已经显示某个关键局限/风险会改变核心结论，但正文完全略去，导致读者被引向明显过度的判断。

**例外**
- 不要求固定反面段落。
- 不要求为了形式上的客观而面面俱到。
- 不要求失败案例。
- 普通的适用边界、尚待观察或“可能还有其他原因”不构成FAIL。

## 四、排比小标题检验

### S005｜小标题关系真实

**Stage**
STRUCTURE

**适用类型**
A / B / C / D / E

**严重级别**
MAJOR

**判定问题**
小标题是并列还是递进？对应的打乱/跳跃测试是否通过？

**通过条件**
并列边界清晰；递进中间环节不可随意删除。

**失败条件**
为凑结构强行拆成三段，案例可互换。

**例外**
- 无


## 五、去尾测试

### S006｜正文先于抒情收尾立住

**Stage**
STRUCTURE

**适用类型**
A / B / C / D

**严重级别**
BLOCKER

**判定问题**
删除最后1-2段抒情收尾后，正文是否仍能独立完成核心任务？

**通过条件**
正文已经立住判断/解释/立场。

**失败条件**
结尾承担了本应由正文完成的论证。

**例外**
- 类型E以信息任务完成为准。
