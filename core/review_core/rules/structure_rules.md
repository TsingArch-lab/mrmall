# 结构规则

> 本文件是人工维护的 Rule Source of Truth。Registry、Gate、Agent、Feedback 均不得反向修改本文件。


## 一、底层逻辑链

### S001｜A/B完整论证闭环

**Stage**
STRUCTURE

**适用类型**
A / B

**严重级别**
BLOCKER

**判定问题**
文章是否完成设问→证据→推导→收束判断，并且正文的主要章节真的在推进解释，而不只是给若干能力标签分别挂上正向案例？

**通过条件**
核心问题、具体证据、必要推导和判断形成可理解的闭环。多个案例可以全部是正向案例，但主要章节至少应通过机制解释、案例差异、决策过程、条件关系或递进关系推进核心判断；读者读完能够说清“为什么这些材料共同支持这个判断”，而不仅是记住企业做了很多事、取得很多成绩。

**失败条件**
缺少核心问题、证据、推导或收束判断中的任一关键环节；或文章虽然形式上有“观点小标题+案例+总结句”，但主要结构实际是“能力标签A→若干成功案例→再次确认A；能力标签B→若干成功案例→再次确认B”。如果段落之间主要累加品牌、项目、活动、首店、销售、客流等正向材料，而没有继续拆出选择标准、作用机制、案例差异或关键决策，仍属于清单式论证。

**例外**
- 反证不再作为每篇文章的固定结构要求。
- 商业合作稿允许使用较多正向案例，也不要求每一章都设置反面材料；关键只看这些案例是否承担真实的分析功能。
- 个别段落用于补充成绩或背景不构成FAIL，只有当这种写法成为正文主要论证方式时才触发。

## 三、反证空间

### S004｜反证内容按需进入正文

**Stage**
STRUCTURE

**适用类型**
A / B / C / D

**严重级别**
MINOR

**判定问题**
正文是否省略了一个已经明显存在、且足以误导读者理解核心结论边界的重要局限？

**通过条件**
一般情况下N/A。文章不需要专门设置反面章节；只要核心判断没有因为省略重大边界而产生实质误导，就视为通过。

**失败条件**
文章材料本身已经显示某个关键局限/风险会改变核心结论，但正文完全略去，导致读者被引向明显过度的判断。

**例外**
- 不要求固定反面段落。
- 不要求为了形式上的客观而面面俱到。
- 不要求失败案例。
- 普通的适用边界、尚待观察或“可能还有其他原因”不构成FAIL。

**判定问题**
小标题是并列还是递进？对应的打乱/跳跃测试是否通过？

**通过条件**
并列边界清晰；递进中间环节不可随意删除。

**失败条件**
为凑结构强行拆成三段，案例可互换。

**判定问题**

## 六、论证推进

### S007｜论证推进与功能增量

**Stage**
STRUCTURE

**适用类型**
A / B / C / D

**严重级别**
MAJOR

**判定问题**
正文每个主要论证单元，相对于前文是否承担了新的论证功能，使读者对核心问题的理解继续推进？即使没有增加新的事实，它是否完成了必要的归纳、关系建立、转折、限定或推论？

**通过条件**
主要段落或章节至少承担一种新的论证功能，包括但不限于：新增关键事实；解释新的作用机制或因果环节；增加成立条件、适用边界或反例；提供具有区分度的新比较；把前文判断继续推到经营结果或决策含义；将分散事实有效归纳为此前尚未明确的关系；或承担不可缺少的承上启下。连续案例允许围绕同一主题展开，但后一个案例应相较前文增加新的机制、条件、类型差异、经营结果或适用边界。

**失败条件**
正文存在明显、连续且占据实质篇幅的低推进内容，主要表现为：已经成立的判断换一组同质案例反复证明，却没有新增机制、条件或差异；事实和机制已经讲清后，又用更抽象的“生态、体系、能力、长期主义”等词重新说一遍，却没有增加解释；铺陈大量背景、数据或案例，但后续核心判断并不依赖这些材料；或新增内容虽然本身成立，却偏离文章核心问题，不能继续推进主要论证。判断时必须使用“删除测试”和“案例边际价值测试”：删除该段后核心理解若几乎无损，且无法回答“这一段/这一案例相较前文多证明了什么”，可判定为低功能增量。

**例外**
- 不要求每句话都提供全新事实；必要的短总结、转场、回扣可以存在。
- 有效归纳不属于重复：如果总结把多个分散事实第一次组织成新的机制、关系或判断，应视为推进。
- 同一主题可以持续深入；只要新增了因果环节、条件、边界、比较、经营结果或决策含义，就不属于原地重复。
- 个别一句或一小段轻微重复不触发 FAIL；只有低推进内容明显、连续并对阅读效率造成实质影响时才触发。
