# 结构规则

> 本文件是人工维护的 Rule Source of Truth。Registry、Gate、Agent、Feedback 均不得反向修改本文件。


## 一、底层逻辑链

### S001｜A/B完整论证闭环

**Stage**
STRUCTURE

**适用类型**
A / B

**严重级别**
BLOCKER

**判定问题**
文章是否完成设问→证据→推导→收束判断，并且正文的主要章节真的在推进解释，而不只是给若干能力标签分别挂上正向案例？

**通过条件**
核心问题、具体证据、必要推导和判断形成可理解的闭环。多个案例可以全部是正向案例，但主要章节至少应通过机制解释、案例差异、决策过程、条件关系或递进关系推进核心判断；读者读完能够说清“为什么这些材料共同支持这个判断”，而不仅是记住企业做了很多事、取得很多成绩。

**失败条件**
缺少核心问题、证据、推导或收束判断中的任一关键环节；或文章虽然形式上有“观点小标题+案例+总结句”，但主要结构实际是“能力标签A→若干成功案例→再次确认A；能力标签B→若干成功案例→再次确认B”。如果段落之间主要累加品牌、项目、活动、首店、销售、客流等正向材料，而没有继续拆出选择标准、作用机制、案例差异或关键决策，仍属于清单式论证。

**例外**
- 反证不再作为每篇文章的固定结构要求。
- 商业合作稿允许使用较多正向案例，也不要求每一章都设置反面材料；关键只看这些案例是否承担真实的分析功能。
- 个别段落用于补充成绩或背景不构成FAIL，只有当这种写法成为正文主要论证方式时才触发。

## 三、反证空间

### S004｜反证内容按需进入正文

**Stage**
STRUCTURE

**适用类型**
A / B / C / D

**严重级别**
MINOR

**判定问题**
正文是否省略了一个已经明显存在、且足以误导读者理解核心结论边界的重要局限？

**通过条件**
一般情况下N/A。文章不需要专门设置反面章节；只要核心判断没有因为省略重大边界而产生实质误导，就视为通过。

**失败条件**
文章材料本身已经显示某个关键局限/风险会改变核心结论，但正文完全略去，导致读者被引向明显过度的判断。

**例外**
- 不要求固定反面段落。
- 不要求为了形式上的客观而面面俱到。
- 不要求失败案例。
- 普通的适用边界、尚待观察或“可能还有其他原因”不构成FAIL。

## 四、排比小标题检验

### S005｜小标题关系真实

**Stage**
STRUCTURE

**适用类型**
A / B / C / D / E

**严重级别**
MAJOR

**判定问题**
小标题是并列还是递进？各章节是否有清晰、稳定的论证边界，对应的打乱/跳跃测试是否通过？

**通过条件**
并列章节各自承担清晰且可区分的论证任务，主要事实、案例、机制和判断有稳定归属；递进中间环节不可随意删除。

**失败条件**
为凑结构强行拆分；并列章节之间边界模糊，大量主要事实、案例、机制或判断可以无障碍地归入其他小标题，导致各部分实际论证对象持续交叉。

**例外**
- 无


## 五、去尾测试

### S006｜正文先于抒情收尾立住

**Stage**
STRUCTURE

**适用类型**
A / B / C / D

**严重级别**
BLOCKER

**判定问题**
删除最后1-2段抒情收尾后，正文是否仍能独立完成核心任务？

**通过条件**
正文已经立住判断/解释/立场。

**失败条件**
结尾承担了本应由正文完成的论证。

**例外**
- 类型E以信息任务完成为准。

## 六、论证推进

### S007｜论证推进与功能增量

**Stage**
STRUCTURE

**适用类型**
A / B / C / D

**严重级别**
MAJOR

**判定问题**
正文各主要段落或章节，相对于前文是否持续增加新的“解释价值”，使读者进一步理解核心问题为什么成立、如何发生、受什么条件影响、或意味着什么？

**通过条件**
主要段落或章节虽然可以围绕同一主题持续展开，但应继续增加新的解释价值，例如：提出此前没有解释过的机制或因果环节；增加新的成立条件、边界或关键变量；建立新的比较或关系；把前文判断推进到新的经营结果、决策含义或更高一层结论；或者第一次把分散事实归纳成此前尚未明确的解释关系。

判断增量的对象不是“这一段新增了什么内容”，而是“这一段新增了什么解释”。新增案例、数字、品牌、人物、概念或措辞，本身不构成论证增量；只有这些材料使读者对“为什么、如何、在什么条件下、因此意味着什么”的理解继续向前，才算有效推进。

**失败条件**
正文存在明显、连续且占据实质篇幅的低推进内容：多个主要段落或章节虽然使用了不同案例、数据、概念或表述，却持续完成同一个已经完成的解释任务，使文章不断证明已经证明过的东西。

典型情形包括：前文已经解释清楚某个判断为何成立，后文只是补充更多同功能案例或数据；同一解释被反复改写成“生态、体系、能力、长期主义、底层逻辑”等不同概念，却没有增加新的机制、条件、关系或推论；某个本应在后文承担的新论点，已被前文提前完整讲掉，导致后文章节虽有新材料，但核心解释被严重预支；总结部分只是再次换一套词汇复述正文已经完成的解释，而没有形成新的归纳关系。

可用删除测试辅助判断：如果删除某一主要段落、章节或一组同质内容后，事实数量会减少，但读者对作者“为什么这么判断”的理解几乎不受影响，则这些内容仍可能属于低增量论证。

**例外**
- 不要求每句话都增加新解释；必要的短总结、转场和回扣可以存在。
- 有效归纳不属于重复：如果总结第一次把前文分散事实组织成新的机制、关系或判断，应视为推进。
- 同一判断可以被继续深化；只要后文真正增加了新的机制、条件、边界、关系或推论，就不属于重复。
- 个别一句或一小段轻微重复不触发 FAIL；只有低推进内容明显、连续并对文章结构或阅读效率造成实质影响时才触发。
