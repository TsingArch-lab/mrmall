# 观点生成规则

> 本文件是人工维护的 Rule Source of Truth。Registry、Gate、Agent、Feedback 均不得反向修改本文件。


## 一、普通观点 vs 高级观点

### I001｜核心判断包含具体机制

**Stage**
INSIGHT

**适用类型**
A / B

**严重级别**
BLOCKER

**判定问题**
如果同行追问‘为什么’，能否回答出具体X如何导致Y？

**通过条件**
至少有一个核心判断明确解释“某个具体动作/选择/机制如何带来某种结果或经营含义”；不要求把所有结果都证明到唯一因果。

**失败条件**
专业、成功、年轻化、长期主义等抽象标签替代机制；或全文主要罗列品牌、活动、销售、客流、首店等成绩，却没有解释它们之间的关系以及为什么这些事实说明核心判断。

**例外**
- 无


## 一、高级观点三个特征

### I002｜高级观点至少满足2项

**Stage**
INSIGHT

**适用类型**
A / B

**严重级别**
BLOCKER

**判定问题**
观点是否具备可证伪、可执行、有归因链条中的至少两项？

**通过条件**
至少2项成立。这里的‘可证伪’指现实中存在明确检验边界，不要求文章主动提供反方案例。

**失败条件**
只有描述性归纳或态度判断。

**例外**
- 不得把‘可证伪’解释为‘必须在正文中自我反驳’。


## 二、五个追问

### I003｜五个追问均已过一遍

**Stage**
INSIGHT

**适用类型**
A / B

**严重级别**
MINOR

**判定问题**
文章是否明显跳过了必要的探索，只沿着一个既定宣传口径或最初结论单线推进？

**通过条件**
五个追问是探索工具，不是成稿必须逐项展示的清单。成稿中只要能够看到至少两种不同角度的有效推导，或已有证据足以形成具体机制判断，即视为通过。

**失败条件**
全文只有单一路径：重复企业口径、重复同一类成绩或重复同一个案例结论，没有比较、拆解、关系解释、历史/数据校验中的任何有效扩展。

**例外**
- 不要求五个追问都在正文中出现。
- 不能因为成稿没有呈现某一追问，就反推作者“没有检查过”。
- 若素材本身单一但已经足以形成清晰机制判断，不构成FAIL。

## 三、失败模式1

### I004｜判断不能只是事实改写

**Stage**
INSIGHT

**适用类型**
A / B / C / D

**严重级别**
BLOCKER

**判定问题**
核心判断是否比“企业做了什么、成绩怎么样、企业自己怎么定义能力”多走了一步，真正产生了可解释的信息增量？

**通过条件**
判断至少完成一种实质推导：解释关键选择为何有效、不同案例为何采用不同路径、某个动作通过什么机制影响结果、多个事实之间存在什么因果/条件/递进关系，或把企业口径翻译成更具体的经营决策逻辑。无需证明唯一因果，但必须让读者获得事实清单本身不能直接提供的理解。

**失败条件**
判断主要是事实或企业口径的再命名：例如“不同项目做了不同定位→说明懂客群”“几个新品牌后来表现好→说明善于识别品牌潜力”“做了很多活动、会员和商户服务→说明链接能力/生态能力强”。如果中间没有进一步说明识别标准、关键决策、作用机制或案例之间的差异关系，即使案例很多、数据具体，也仍属于“成绩/动作→能力标签”的直接跳跃。

**例外**
- 类型E不适用。
- 不要求每个段落都提出新理论；文章只要围绕核心判断形成足够的实质推导即可。
- 已经解释清楚机制后，用一两个案例补充验证不属于重复改写。
